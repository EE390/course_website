At a glance

A microcontroller is a whole small computer on one chip: a CPU, memory for the program (flash), memory for data (RAM), and peripherals such as timers, a serial port and I/O pins. The 8051 architecture was introduced by Intel in 1980 and is still made today by many companies. STC's STC89C52RC runs the same instruction set, so everything you learn about the 8051 applies to it.

CPU8-bit 8051 core, standard 8051 instruction set
Program memory8 KB flash (0000H–1FFFH), rewritable over the serial port (ISP)
Data memory512 B RAM: 256 B standard internal RAM + 256 B auxiliary RAM
Non-volatile dataInternal EEPROM area written through IAP: 6 KB as reported by the course board's chip (some datasheet tables list 4 KB). The board also has a separate AT24C02 chip.
Peripherals3 × 16-bit timer/counters (T0, T1, T2), 1 × UART, watchdog timer
Interrupts8 sources, 4 priority levels (6 usable on the 40-pin package)
I/O32 pins in four 8-bit ports P0–P3 (40-pin DIP package)
Supply3.3–5.5 V (the board uses 5 V from USB)
ClockExternal crystal, up to 48 MHz in 12T mode. The board uses 11.0592 MHz

Inside the chip

Every block sits on a shared internal bus. The CPU fetches an instruction from flash, decodes it, and reads or writes RAM or a peripheral. Peripherals are controlled through special function registers (SFRs): memory addresses that are really control knobs. Writing TMOD configures the timers, and writing P2 sets the pins of port 2.

The minimum circuit

A bare microcontroller does nothing on its own. The minimum system is the smallest circuit that makes it run your program. It has power, a clock, a reset and the EA pin tied high. To load programs you add a fifth part, the download circuit. Your development board contains all of these, plus the peripherals.

PartPartsWhy it's needed
Power5 V to pin 40, GND to pin 20, 100 nF capacitor (C4) right next to the chipThe chip runs on 3.3–5.5 V. The small capacitor supplies the fast current spikes when the logic switches, keeping the supply clean.
Clock11.0592 MHz crystal between pins 18 and 19, two 33 pF capacitors (10–33 pF) to GNDThe crystal and the chip's internal amplifier form an oscillator: the "heartbeat" that steps the CPU through instructions and drives the timers. The capacitors let it start and run stably.
Reset10 µF capacitor from 5 V to RST, 10 kΩ resistor from RST to GND, push button across the capacitorAt power-on the uncharged capacitor holds RST high briefly, so the chip starts from a known state. Pressing the button pulls RST high again to restart the program.
EAPin 31 to 5 VTells the CPU to fetch code from its internal flash instead of an external memory chip.
DownloadUSB-to-serial chip (CH340) on P3.0/P3.1, sharing GNDA PC has no 8051 serial pins, so the CH340 turns USB into the chip's TTL-level UART. It is used both for programming and for talking to your program.

Build it on a breadboard

You can run the STC89C52RC without the development board. You need everything in the table above, plus a USB-to-TTL serial adapter (CH340 or similar) set to 5 V.

  1. Place the chip, wire VCC (40) and GND (20), and put the 100 nF capacitor across them as close as you can.
  2. Add the crystal and its two capacitors on pins 18/19, keeping the wires short.
  3. Add the reset capacitor, resistor and button on pin 9, and tie EA (31) to 5 V.
  4. Connect the adapter: adapter TXD → P3.0 (pin 10), adapter RXD → P3.1 (pin 11), GND → GND. Transmit always goes to receive.
  5. Power the chip through a switch you can toggle, because programming needs a power cycle (see Programming the chip).
  6. Test with an LED and a 1 kΩ resistor from 5 V to P1.0 and the program CLR P1.0 followed by SJMP $.

Tip: if the download never starts, the chip may still be getting power through the adapter's TXD line even with VCC switched off, so it never truly powers down. A 1 kΩ resistor in series with that line usually fixes it.

Clock & timing

In the default 12T mode the CPU divides the crystal frequency by 12. One machine cycle is 12 oscillator periods, and the timers count once per machine cycle.

machine cycle = 12 / 11 059 200 Hz ≈ 1.085 µs  ·  timer counts per second = 11 059 200 / 12 = 921 600
  • Each instruction takes 1, 2 or 4 machine cycles. For example MOV A,R0 takes 1, DJNZ and LCALL take 2, and MUL AB/DIV AB take 4. That is how software delay loops can be timed.
  • Why 11.0592 MHz and not 12 MHz? It divides exactly into the standard serial baud rates. At 12 MHz the nearest rates you can make are 8 929 or 10 417 baud, 7–8.5% off, which is too far for reliable serial communication.
  • 6T mode (the STC-ISP option “Enable 6T (double-speed) mode”) makes the CPU and timers twice as fast. Leave it unchecked: all course timing values assume 12T.

Example, a 1 ms delay with Timer 0: 1 ms × 921 600 = 921.6 → 922 counts. Mode 1 overflows at 65 536, so load 65 536 − 922 = 64 614 = FC66H. The course examples use FC67H, which is one count less and still 1 ms to within 0.1%.

Timing a software delay loop

A delay loop wastes time by counting down registers. Its length is the number of machine cycles it executes (see the instruction table):

DELAY:  MOV  R6,#200       ; 1 cycle
OUTER:  MOV  R7,#250       ; 1 cycle     INNER:  DJNZ R7,INNER      ; 2 cycles     > outer loop: runs 200 times
        DJNZ R6,OUTER      ; 2 cycles    /  (inner DJNZ runs 250 times each)
        RET                ; 2 cycles
cycles = 1 + 200 × (1 + 2×250 + 2) + 2 = 100 603 ≈ 109 ms

Software delays are easy but imprecise. Interrupts that run during the loop make it longer, 6T mode halves it, and the CPU can do nothing else while it runs. Use a timer when the timing matters.

Reset & start-up

When RST goes high (power-on or the reset button), the chip loads fixed values into its registers. When RST goes low again it starts running at address 0000H. That is why every program starts with ORG 0000H.

RegisterValue after resetWhat it means for you
PC0000HThe first instruction is fetched from address 0000H.
P0–P3FFHAll pins start HIGH, so they work as inputs, and active-low LEDs start off.
SP07HThe first PUSH/LCALL writes to 08H, on top of register bank 1. Programs that use banks 1–3 or a lot of stack should move it, e.g. MOV SP,#5FH.
A, B, PSW, DPTR00HRegister bank 0 selected, carry clear.
TMOD, TCON, SCON, IE00HTimers stopped, serial port off, all interrupts disabled until you enable them.
RAM 00H–7FHunchanged / randomA reset keeps RAM, but after power-on it holds garbage. Always initialise variables.

On the STC chip a small ISP boot program runs before your code after a power-on. It is what makes serial programming possible (see Programming the chip). If no PC is trying to program the chip, it jumps to your program within a fraction of a second, so you won't notice it.

Because the 8051 is a Harvard architecture, code and data live in separate spaces. The same address, e.g. 0030H, means different memory depending on the instruction: MOVC reads flash, MOV reads RAM, and MOVX reads auxiliary or external RAM.

Flags & arithmetic

The program status word PSW (D0H) holds the flags set by arithmetic, and selects the register bank.

BitFlagMeaning
7CY (C)Carry out of bit 7 after an add, or borrow after a subtract. Also the 1-bit “accumulator” for bit operations.
6ACAuxiliary carry out of bit 3. Used by DA A for BCD.
5F0Free flag for your own use
4–3RS1 RS0Register bank select: 00 = bank 0 (00H–07H), 01 = bank 1 (08H–0FH), 10 = bank 2 (10H–17H), 11 = bank 3 (18H–1FH)
2OVSigned overflow: the result doesn't fit in −128…+127
0PParity of A: 1 if A contains an odd number of 1s
  • Change the flags: ADD, ADC, SUBB (CY, AC, OV); MUL and DIV (CY cleared, OV); CJNE, RLC, RRC, DA A (CY); and SETB C, CLR C, CPL C.
  • Do not change the carry: INC, DEC, MOV, ANL/ORL/XRL on A, RL/RR. The P flag always follows A.
  • SUBB always subtracts the carry too. Do CLR C before a single-byte subtraction.
  • Multi-byte numbers: add the low bytes with ADD, then the high bytes with ADC so the carry is included.
  • MUL AB puts the 16-bit product in B (high) and A (low); OV = 1 if it's larger than 255. DIV AB puts the quotient in A and the remainder in B; OV = 1 on division by zero.
  • Signed numbers use two's complement (−1 = FFH). Check OV, not CY, for signed overflow.

Comparing numbers with CJNE

There is no “compare” instruction. CJNE jumps if the values differ, and sets CY = 1 if A is less than the other value (unsigned):

        CJNE A,#50,NOT_EQUAL   ; A = 50?
        SJMP IS_EQUAL          ; yes
NOT_EQUAL:
        JC   IS_LESS           ; CY = 1 → A < 50
        ...                    ; otherwise A > 50

Converting a value for a display: MOV B,#10 then DIV AB splits A into tens (A) and ones (B). Adding 30H turns a digit 0–9 into its ASCII character for the LCD or serial port.

Stack & subroutines

The stack is an area of internal RAM that grows upwards. SP points to the last byte stored:

  • PUSH x: SP ← SP + 1, then the byte is stored at SP. POP x: the byte at SP is read, then SP ← SP − 1.
  • LCALL/ACALL push the return address (2 bytes, low byte first) and jump. RET pops it back into PC. An interrupt does the same, and RETI returns from it.
  • Every nested call uses 2 more bytes, and so does every interrupt, on top of anything pushed.

Move the stack at the start of every program. After reset SP = 07H, so the stack grows into register banks 1–3 and your variables. MOV SP,#5FH gives the stack 60H–7FH (32 bytes) and leaves 30H–5FH free for variables.

Writing a subroutine

; SHOW_DIGIT: display the digit in A on the 7-segment display.
; Input: A = 0..9   Changes: nothing (saves what it uses)
SHOW_DIGIT:
        PUSH ACC               ; PUSH/POP need a direct address: ACC, not A
        PUSH DPH
        PUSH DPL
        MOV  DPTR,#SEG_TABLE
        MOVC A,@A+DPTR         ; digit → segment pattern
        MOV  P0,A
        POP  DPL               ; restore in the REVERSE order
        POP  DPH
        POP  ACC
        RET
  • Document each subroutine's inputs, outputs and which registers it changes. A common convention is to pass values in A or R7 and return results in A.
  • To save R0–R7, push their RAM address (bank 0: R0 = 00H … R7 = 07H), e.g. PUSH 07H.
  • Every PUSH needs a matching POP before RET. Otherwise RET pops the wrong bytes and the program jumps to a random address.
  • An ISR can switch to its own register bank instead of saving R0–R7: PUSH PSW, MOV PSW,#08H (bank 1), and POP PSW before RETI.

I/O ports

Each port is an SFR (P0=80H, P1=90H, P2=A0H, P3=B0H) and each bit is one pin. Write the whole port (MOV P2,#0FEH) or one bit (CLR P2.0), and read the same way (MOV A,P3, JB P3.1,label).

How a pin works: “quasi-bidirectional”

P1, P2 and P3 have no direction register. Each pin has a strong transistor to GND and a weak pull-up to VCC:

  • Write 0: the strong transistor pulls the pin LOW and can sink several mA, enough for an LED.
  • Write 1: only the weak pull-up holds the pin HIGH. It can source very little current, but anything outside can easily pull it LOW.
  • To use a pin as an input, write 1 to it first (it already is 1 after reset), then read it. A pressed button shorts the pin to GND, so it reads 0.

That's why the board's LEDs are active-low: each LED goes from 5 V through a resistor to the pin, so the pin sinks the current when you write 0. Driving an LED from the weak HIGH level would barely light it.

Port 0 is different: it is open-drain, with no pull-up at all. It can only pull LOW, so writing 1 leaves the pin floating unless there is an external pull-up resistor. The board has pull-ups on P0, but a breadboard circuit needs them too (about 10 kΩ).

For which board module is on which pin, see the pin map.

Timers

A timer is a 16-bit counter (THx:TLx) that counts up once per machine cycle. When it rolls over from FFFFH to 0000H it sets its overflow flag TFx, and can trigger an interrupt. As a counter (C/T = 1) it counts pulses on pin T0 (P3.4) or T1 (P3.5) instead.

  • Mode bits: TMOD = 01H puts Timer 0 in mode 1, 10H Timer 1 in mode 1, 11H both, 21H Timer 1 in mode 2 and Timer 0 in mode 1. TMOD is not bit-addressable, so write the whole byte once at start-up.
  • C/T: 0 = timer (counts machine cycles). 1 = counter (counts falling edges on pin T0/P3.4 or T1/P3.5, e.g. to count pulses from a sensor).
  • GATE: 0 = the timer runs whenever TRx = 1. 1 = it runs only while TRx = 1 and the INTx pin is HIGH, which measures how long a pulse lasts.
  • TRx starts (1) and stops (0) the timer. TFx is set on overflow and must be cleared by you, unless its interrupt is used.

Delays with a timer

reload = 65536 − (delay in seconds × 921600)

In mode 1 the longest single delay is 65 536 counts ≈ 71 ms. For longer delays, repeat a shorter one in a loop. The standard polled pattern (Timer 0 in mode 1, set once with MOV TMOD,#01H):

DELAY_1MS:
        MOV  TH0,#0FCH     ; FC67H = 64615 → 921 counts ≈ 1 ms
        MOV  TL0,#67H
        SETB TR0           ; start Timer 0
        JNB  TF0,$         ; wait here until it overflows
        CLR  TR0           ; stop it
        CLR  TF0           ; clear the flag for next time
        RET

Polling blocks the program while it waits. With the timer interrupt the main program keeps running and the ISR handles each overflow. In mode 2 the timer reloads itself from THx, which gives perfectly regular overflows up to 256 counts (≈ 278 µs) apart. That is why it's used for baud rates.

See Timer 0 generating tones and Timer 1 as a 5 ms time base in the Bird Sound Synthesizer project.

Interrupts

An interrupt lets hardware pause your main program to run a short routine, the interrupt service routine (ISR), then resume exactly where it left off. You don't need to keep checking flags in a loop.

  1. Enable the source and the global switch in IE, e.g. SETB ET0 and SETB EA, or MOV IE,#82H.
  2. When the event happens its flag is set. The CPU finishes the current instruction, pushes the PC onto the stack and jumps to the vector address.
  3. For timer and edge-triggered external interrupts the flag is cleared automatically. For the serial port you must clear RI/TI yourself.
  4. The ISR ends with RETI (not RET), which pops the PC and re-enables interrupts of that priority level.

ISR rules: keep it short. If you change A, PSW or R0–R7, save them with PUSH/POP, because the main program was using them. Put LJMP at the vector, because there are only 8 bytes before the next one.

Program layout with an interrupt

        ORG  0000H
        LJMP MAIN              ; skip over the vector table
        ORG  000BH             ; Timer 0 vector
        LJMP T0_ISR

        ORG  0030H             ; main program starts after the vectors
MAIN:   MOV  SP,#5FH
        MOV  TMOD,#01H         ; Timer 0, mode 1
        MOV  TH0,#...          ; first reload value
        MOV  TL0,#...
        SETB ET0               ; enable the Timer 0 interrupt
        SETB EA                ; enable interrupts globally
        SETB TR0               ; start the timer
LOOP:   ...                    ; the main program keeps running
        SJMP LOOP

T0_ISR: PUSH ACC               ; save everything the ISR changes
        PUSH PSW
        ...                    ; reload TH0/TL0 (mode 1), do the work
        POP  PSW
        POP  ACC
        RETI

Enable, trigger and priority

Register76543210

  • External interrupts (INT0 = P3.2, INT1 = P3.3) are set by IT0/IT1 in TCON. IT0 = 1 means falling-edge triggered: one interrupt per high-to-low change. IT0 = 0 means low-level triggered: it keeps interrupting for as long as the pin stays LOW, which is rarely what you want for a button.
  • Priority: setting a bit in IP makes that source high priority. A high-priority interrupt can interrupt a low-priority ISR, but not the other way round.
  • Same priority: if two interrupts are pending at once they are served in the order INT0 → Timer 0 → INT1 → Timer 1 → Serial → Timer 2.

Communicating with the chip

Serial port (UART) ↔ your PC

The UART sends bytes one bit at a time on TXD (P3.1) and receives on RXD (P3.0). On the board these pins go to the CH340 chip, which appears on your PC as a COM port. That is the same USB cable you program with.

        MOV TMOD,#20H   ; Timer 1, mode 2 (8-bit auto-reload) = baud rate generator
        MOV TH1,#0FDH   ; 9600 baud at 11.0592 MHz
        MOV SCON,#50H   ; UART mode 1 (8N1), receiver enabled (REN = 1)
        SETB TR1        ; start the baud rate timer

        MOV SBUF,#'A'   ; send a byte ...
        JNB TI,$        ; ... wait until it has gone out
        CLR TI

        JNB RI,$        ; wait for a byte from the PC
        MOV A,SBUF      ; read it
        CLR RI
baud = 2SMOD × fosc / (384 × (256 − TH1))  →  11 059 200 / (384 × 3) = 9600 with TH1 = FDH

Close the terminal before you program the board, because only one program can use the COM port at a time. Full example: Serial Terminal: Read/Write RAM.

C with SDCC

Everything on this page applies to C as well: the same chip, registers, timers and interrupts. In C you write TMOD = 0x01; instead of MOV TMOD,#01H, and the compiler produces the instructions. The course uses SDCC, a free 8051 C compiler (see Getting Started for installation).

  1. .cyour source
  2. sdcc -mmcs51compile + link
  3. .ihxIntel HEX
  4. packihxtidy the HEX
  5. .hexopen in STC-ISP

build.bat runs both commands. SDCC also writes useful side files: .rst (your C lines with the assembly generated for each), .mem (how much RAM and flash is used) and .map (where every variable and function ended up).

Program layout

#include <8052.h>              /* names for all SFRs and bits: P1, TMOD, TR0, P2_5 … */

#define LED   P2_0              /* give pins meaningful names */
#define K1    P3_1

void main(void)
{
    TMOD = 0x01;                /* set up the hardware once */

    for (;;) {                  /* main() must never return */
        if (!K1)                /* button pressed (reads 0) */
            LED = 0;            /* LED on (active LOW) */
        else
            LED = 1;
    }
}

Registers and pins

  • Whole registers use their datasheet names: P1 = 0xF0; TH0 = 0xFC; x = SBUF;
  • Single bits use an underscore instead of a dot: P2_5 is pin P2.5. Named bits work directly: TR0 = 1; if (TF0) EA = 0;
  • To name a pin, use #define BUZZER P2_5. SDCC also lets you declare your own: __sbit __at (0xA5) BUZZER; and __sfr __at (0x90) PORT1;.
  • To change some bits of a port and leave the rest alone, mask them: P2 = (P2 & 0xE3) | (digit << 2); changes only P2.2–P2.4.

C: memory, interrupts & timing

Where your data goes

SDCC's default small model keeps variables in the 256 bytes of internal RAM, and the stack uses whatever RAM is left. RAM is the scarcest resource on the chip, so it matters where data ends up:

DeclarationStored inNote
unsigned char count; (global)Internal RAM1 byte of RAM
const unsigned char TABLE[] = {…};FlashNo RAM used. Use this (or __code) for every lookup table.
unsigned char TABLE[] = {…}; (not const)RAM and flashCopied into RAM at start-up. A 1 KB sound table simply won't fit.
Local variablesFixed RAM locationsBy default SDCC functions are not reentrant: locals are not on the stack.
"text" string literalsFlashPass them as const char *.

Check the result in the .mem file after every build. It shows the RAM map and the flash size (the STC89C52RC has 8 KB).

Interrupts in C

volatile unsigned char ticks;           /* shared with the ISR */

void timer0_isr(void) __interrupt(1);   /* prototype: REQUIRED in the file with main() */

void timer0_isr(void) __interrupt(1)    /* 1 = Timer 0 */
{
    TH0 = 0x4C;                         /* keep it short: reload, count, set a flag */
    TL0 = 0x00;
    ticks++;
}
__interrupt(n)012345
SourceINT0Timer 0INT1Timer 1SerialTimer 2
Vector0003H000BH0013H001BH0023H002BH
  • The prototype must be visible in the file that contains main(). If it's missing, SDCC doesn't put the LJMP at the vector, and the interrupt silently never runs.
  • Don't call functions from an ISR. SDCC then saves A, B, DPTR, PSW and R0–R7 on every interrupt: 15 pushes plus 15 pops, which is slow, and the called function isn't reentrant either. A simple ISR that only reads and writes SFRs and globals generates no saving at all, the same code as in assembly.
  • Shared variables should be volatile, so the compiler re-reads them every time.
  • Multi-byte updates must not be interrupted halfway. Protect them with EA = 0; … EA = 1; or with __critical { … }.

Timing

Don't time things with empty loops in C: their length depends on the compiler and its options. Use a timer, exactly as in assembly:

void delay_1ms(void)                    /* Timer 0 in mode 1, set once: TMOD = 0x01 */
{
    TH0 = 0xFC;  TL0 = 0x67;            /* 921 counts ≈ 1 ms */
    TR0 = 1;
    while (!TF0) ;
    TR0 = 0;  TF0 = 0;
}

Programming the chip

Getting your program onto the chip takes two steps. First the assembler turns your source into machine code. Then the programmer sends that code over the serial port to the boot program inside the chip, which writes it into flash.

  1. .asmyour source code
  2. MIDE-51assembles it
  3. .hexmachine code (Intel HEX)
  4. STC-ISPon the PC
  5. USB → CH340becomes UART
  6. ISP boot programin the chip, on P3.0/P3.1
  7. Flashruns from 0000H

What's in a .hex file

An Intel HEX file is plain text you can open in Notepad. Each line is one record. For the first program in Getting Started (CLR P2.0, machine code C2 A0) it looks like this:

:02 0000 00 C2A0 9C      ← 2 bytes, at address 0000H, type 00 (data), bytes C2 A0, checksum 9C
:00 0000 01 FF           ← type 01: end of file

Spaces added for readability; the real file has none. The checksum makes all bytes on the line add up to 00H, so STC-ISP can detect a corrupted file.

Why you have to power-cycle the board

STC chips don't need a separate hardware programmer, because a small ISP (In-System Programming) boot program is stored in a protected part of the flash. It runs only right after power-on:

  1. You click Download/Program. STC-ISP starts sending a handshake pattern on the COM port again and again (“Checking target MCU…”).
  2. You switch the board off and on. The boot program starts and listens on RXD for a moment.
  3. It hears the handshake and replies with the chip's model and firmware version. STC-ISP then sends your code, which the boot program writes into flash and verifies.
  4. After “Complete!” the chip starts your program at 0000H. If no handshake arrives after a power-on, the boot program jumps straight to your program.

Pressing the reset button doesn't work for this: the boot program only listens after a real power-on, which is why it's called a cold start. (The board maker's own PZ-ISP tool can trigger this automatically, but the course uses STC-ISP.)
